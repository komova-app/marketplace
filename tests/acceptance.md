# Komova marketplace package acceptance

These checks define the product documentation delivered by this repository. They do not authorize a production connection or a tester invitation.

1. **Complete plugin installation:** the English README directs users to install the complete package from this marketplace: MCP connection, skill, product references, and four local guides. Claude and supported OpenAI clients have distinct installation instructions and account authorization remains explicit. An MCP-only connector is never presented as installing the plugin; desktop limitations are visible. No API source checkout or separate skill installation is required to use its documentation. An empty authorized account is distinguished from a failed connection.
2. **Requested reads and writes:** the skill chooses tools within the person's request and honors explicit review boundaries without imposing a mandatory first-use sequence or repeated approvals for authorized writes. It reads current records, uses exact UUIDs, verifies relevant saved fields, and checks uncertain outcomes before retrying. Installation, account authorization, successful reads, and verified writes remain distinct facts.
3. **Product model:** a reader can distinguish Project, Item, Form, Entry, Reminder, Feedback, and ChangeEvent; status from assignee; a prerequisite from `blocked`; and a locally saved Form draft from a submitted answer. The guide states where List, Item detail, and Feed show each result.
4. **Tool contract:** every exported MCP tool appears once in the tool reference with its current input names and a practical use. Important validation and side effects are explicit. Mobile REST operations are not advertised as MCP tools.
5. **Feed narrative:** the reference shows how to write a durable Entry with its event, outcome, reason, evidence, and limits in natural prose, using structured HTTPS sources. It distinguishes an Entry from a short immediate Reminder and explains Feed paging and full-detail access.
6. **Boundaries:** the install package contains no coordinator tick, Project Manager, lease-renewal schedule, or automatic project-review procedure. It contains no secret, private credential, complete OAuth redirect URL, or claim that refresh-token exchange or revocation was verified.
7. **Package integrity:** manifest JSON parses, the MCP URL is canonical, all skill reference links resolve inside the plugin, and all four local guide files are present. The package's own tool inventory can be checked without an API checkout; maintainer checks additionally compare it and packaged guide contents with the API source when available. Agent-facing static instructions, metadata, references, and guides are English; account text and mobile UI localization remain independent.
8. **Saved Form evidence:** the 39-tool reference includes the private read-only `get_form_attachment` call. The app guide distinguishes upload drafts from saved evidence, explains account quota and owner deletion without changing answers or verdict, and exposes no public file URLs. Installed 37-tool and 38-tool catalogs are described as separate server/client states, not evidence that every documented capability is available.
9. **Project deletion:** the package documents `delete_project(project_id)` as a destructive operation requiring explicit confirmation of the exact current Project and its deletion scope. It removes contained work and related saved evidence while preserving inbox Items and other Projects. Confirmation already given for that exact Project is reused; ordinary authorized writes remain free of mechanical approval steps. Success is `deleted=true` plus absence from current reads; an uncertain outcome or retry that finds no Project is not reported as another confirmed deletion. The exported tool has `destructiveHint=true`. Synchronization invalidates current state without retaining the deleted Project's ID or name as a tombstone.
10. **Standalone English guides:** package tests run with no sibling API checkout and verify all four guide snapshots under `references/guides/` are present, English, and linked from the skill. The package's relative documentation links resolve locally, its own catalog contains 39 tools, and no guide needs workspace files or internal coordination instructions. When API source is available, an additional maintainer check verifies snapshot parity; that check is not a runtime installation requirement.

11. **OAuth clients:** the installed skill contains local connection guidance for ChatGPT, Codex, Claude web, Claude Code, OpenCode, Hermes and OpenClaw. It distinguishes a model provider such as DeepSeek from the client hosting it, and server protocol integration tests from a real client's completed login. It explains CIMD and public DCR without presenting a self-declared client name as verified branding, or exposing credentials or full authorization URLs. Connection snippets use the canonical MCP endpoint and primary client documentation.

Run `node --test tests/package.test.mjs` from this repository. Review the first five scenarios against the rendered README and skill references before changing or publishing the marketplace.
