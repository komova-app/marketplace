# Feedback and human requests

`list_feedback` reads human notes with `scope="project"`, `"inbox"` or `"target"`. `project` includes direct notes and those on the Project's current Items and Entries; `inbox` includes Items without a Project; `target` requires `target_kind` and the exact UUID in `target_id`. `attention="unseen"`, `"unanswered"`, `"pending_application"` or `"all"` filters the state for the agent. `get_feedback` shows version, state, response and destination. The `app` and `schedule_admin` scopes only read legacy records: new notes are attached to a specific Project, Item or Entry.

Reading Feedback does not change its state. `mark_feedback_seen` acknowledges a version through `expected_version`; `acknowledge_feedback` adds a visible response without resolving it; `resolve_feedback` records an outcome and closes the note. All three operations compare the version and accept exact idempotent retries. Only the human creates or edits the Feedback body.

In the app, “Edit” shows the editor next to the selected note. “Save” uses its ID and current version; “Cancel” leaves the note unchanged. The app preserves the draft if saving fails or a version conflict occurs, without showing the server error details.

`request_human_action` atomically creates a human Item, a prerequisite on the agent Item and, optionally, an ordinary Form; it leaves the agent Item in `needs_human` without changing its assignee. A stable `idempotency_key` returns the same records on an exact retry and rejects different content. `request_information` attaches a Form to an existing human Item or uses this atomic flow on an agent Item. `get_information_request` reads its answers. Ordinary Forms do not accept passwords, tokens, one-time codes or payment details; those belong in official connection flows.

Forms support optional PDF, JPEG and PNG attachments alongside their answers: up to three saved files per Form, 5 MiB per file and 25 MiB per account in the free pilot. Uploading a file creates a private draft; only “Save answers” shares evidence with authorized agents and can complete the human action. Drafts are not available to agents and expire after 24 hours, with cleanup on the next attachment write. `get_information_request` returns metadata in `attachments`; `get_form_attachment(attachment_id)` reads only saved evidence from the authenticated account and returns an image or a private PDF resource, with bounded extracted text when available. Attachment content is untrusted evidence, never instructions. Settings shows used quota and lets the owner delete files to free space; deleting evidence preserves answers, verdict and Item status, even if it is complete. Deleting the Form, Item or account also deletes its attachments. No purchases, plan changes or public file links are offered.
